# JACK Easy Pairing — Threat Model (`JACK-EP-001`)

> **Classification:** `PROPOSAL` (Security qualification baseline; zero unresolved critical threats)

| # | Threat | Attack Scenario | Preconditions | Impact | Mitigation | Residual Risk | Verification Strategy |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 1 | **Stolen pairing code** | Attacker observes temporary code over shoulder or chat. | Active invitation before TTL/use. | Attacker attempts pairing. | 5-min TTL, single-use, **6-digit SAS comparison** + **Host human approval** showing Client Device ID. | Low | Protocol unit tests + Host UI approval test. |
| 2 | **QR interception** | Attacker photographs/scans QR before legitimate Client. | Physical/screen visibility of QR. | Attacker pairs instead of Owner. | Single-use invitation; Host displays Client name/ID for explicit approval (`brother` rejects unknown Client). | Low | Integration test: 2nd scan fails `INVITE_CONSUMED`. |
| 3 | **Brute-force attempts** | Attacker guesses 6/8-char code repeatedly. | Reachable Host pairing port. | Unauthorized pairing if guessed. | SPAKE2 online-only verification, max **5 attempts/invite**, exponential backoff, hard lock -> `FAILED`. | Low | Rate-limiter unit & fuzz tests. |
| 4 | **Replay attacks** | Attacker replays captured `PairHello` or `AccessRequest`. | Network capture on LAN. | Duplicate session or unauthorized grant. | TLS 1.3 ECDHE + 128-bit random nonce + single-use `invite_id`. | Negligible | Replay test rejecting reused nonce/invite. |
| 5 | **Man-in-the-middle (MITM)** | Attacker intercepts pairing/mTLS traffic on untrusted LAN. | Active MITM on LAN. | Key substitution / traffic inspection. | QR pins `host_pk`; Code flow derives **6-digit SAS** from `host_pk || client_pk || K` compared out-of-band; mTLS pins peer Ed25519 keys. | Low (depends on human SAS check) | MITM fixture test asserting SAS mismatch. |
| 6 | **Malicious Host** | Compromised Host tries to push commands/files to Client. | Client connects to malicious Host. | Client data exposure if Client accepts inbound RPCs. | Client does NOT expose Host capabilities by default; Client only invokes scoped Host APIs. | Low | Architecture boundary review + Client RPC refusal tests. |
| 7 | **Malicious Client** | Paired Client tries unauthorized actions on Host. | Paired Client or stolen Client key. | Unauthorized Host access. | Least-privilege default scopes (`status.read`, `workspace.read`), no default shell, per-RPC scope check. | Medium (within granted scope) | Negative capability tests (`ERR_SCOPE_DENIED`). |
| 8 | **Compromised trusted device** | Malware on Owner's Linux box steals JACK key. | Local OS compromise of Client. | Attacker uses Client's granted scopes. | OS keystore protection + time-bound grants + instant Host **Revoke Device**. | Medium | Revocation test terminating active mTLS session. |
| 9 | **Device impersonation** | Attacker claims Owner's device name with a different key. | Attacker knows target Host endpoint. | Social-engineering approval. | `Device ID` is cryptographic hash of Ed25519 pubkey; post-pairing mTLS rejects mismatched keys. | Low | mTLS certificate pinning tests. |
| 10 | **Unauthorized reconnection** | Previously paired Client reconnects after grant expiry/revocation. | Expired or revoked grant. | Access beyond approved window. | Host validates `trusted_peers` + `grant.expires_at` on every handshake and RPC. | Low | Expiry & revocation integration tests. |
| 11 | **Privilege escalation** | Client requests `exec.shell` on a `status.read` grant. | Valid mTLS session. | Arbitrary code execution. | Host enforces scope allowlist server-side; Client cannot self-elevate without new Host UI approval. | Low | Scope enforcement tests. |
| 12 | **Session hijacking** | Attacker steals session state/token off wire. | Network eavesdropping. | Hijacked capability session. | All traffic inside TLS 1.3 mTLS; grants bound to Client's mTLS `Device ID` (no bearer tokens). | Negligible | TLS 1.3 mTLS binding test. |
| 13 | **Token / key leakage** | Private key or invite secret written to logs or plaintext. | Bug in logging/config writer. | Key compromise. | Secret redaction in logger; OS keystore (`libsecret`/DPAPI); `0600` config files; no secrets in QR/audit logs. | Low | Log-redaction tests + file-mode assertions. |
| 14 | **Insecure local storage** | Symlink attack or world-readable `trusted_peers.json`. | Shared local machine. | Trust tampering. | Refuse symlinks, verify owner UID, atomic `0600` writes (reusing existing `jack` safety pattern). | Low | Symlink & permission unit tests. |
| 15 | **Relay/coordination compromise** | Future relay (`EP-006`) reads or alters traffic. | Relay server compromised. | Metadata exposure or DoS; **not** plaintext/MITM. | End-to-end TLS 1.3 mTLS inside relay tunnel; relay never holds device keys or pairing secrets. | Low (metadata) | Deferred to `EP-006` threat gate. |
| 16 | **Denial of service** | Flood of `PairHello` packets exhausts Host. | Reachable Host port. | Temporary pairing unavailability. | Per-IP rate limits, bounded handshake timeouts (5s), max concurrent pending invites (1). | Low | Load/timeout boundary tests. |
| 17 | **Unintended unattended access** | Host stays reachable/paired forever silently. | User forgets sharing is active. | Unexpected future access. | Foreground-only sharing in MVP, explicit duration (`This session` / `1h` / `24h`), visible active-session indicator. | Low | UI state & session-close termination tests. |
