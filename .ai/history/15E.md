# Slice 15E — Installer consent-window hardening

Baseline: b5241d05ba2634782d5a9f55851e17358a6dc96a.
Branch: fix/15e-installer-consent-race.

## Root cause and minimal fix

The old two-path ln invocation could reinterpret the final jack destination as a
directory after the consent prompt. Both a directory and directory symlink caused
an unintended inner jack link and false success.

After consent, parent creation and the existing parent safety checks, the shared
installer now refuses any occupied destination, including dangling links. It then
changes directory in a subshell to the verified installation parent and invokes:

    ln -s "$JACK_SRC" .

Both existing platform wrappers supply a source basename of jack. The explicit directory operand fixes the single leaf at ./jack; a leaf
created after the check is not reinterpreted as another container. No force,
replacement, recursive cleanup, GNU-only flags or new dependency is used.

Existing platform wrappers, CLI, uninstall flow, consent prompts and successful
installation messages are unchanged. No version/release/configuration changes.

## Portability and limits

The implementation uses Bash 3.2-compatible constructs and ordinary ln -s.
Apple's published ln implementation was inspected: its directory operand appends
the source basename once and then attempts symlink creation without force flags:
https://github.com/apple-oss-distributions/file_cmds/blob/main/ln/ln.c

Darwin dispatch on Linux is not native Mac verification. Native macOS/system
Bash 3.2 acceptance remains NOT_RUN. Directory hierarchy replacement/rename,
source relocation and other hostile same-user concurrent mutations are not
claimed to be fully protected. No global lock or transactional rollback added.
