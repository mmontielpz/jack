## Implementation

Added `jack update` and `jack update --help`, reusing the lifecycle checkout
resolver and installation diagnostics. The command prominently states that it
performs no update. It reports the trusted local source, full commit, branch or
detached HEAD, up to 20 exact local v-numbered tags, tracking ref if locally
available, working-tree state and installation-link relationship. No tag implies
publication; no local ref implies remote freshness. No target version is selected.

The command uses a fixed set of local Git queries, with optional writes,
fsmonitor, untracked cache and automatic maintenance disabled. Git transports and
lazy fetching are blocked. Inherited GIT_* variables are cleared in each query's
subshell, including repository redirects, injected config and trace destinations.
Configured filters cause status inspection to be skipped (unknown, exit 1), since
Git can execute clean filters while hashing files. Submodule contents are not
inspected; large working-tree scans have no hard wall-clock timeout.

Exit 0 means the local plan completed, even if dirty or the installed link needs
attention; it does not establish update availability or installation health.
Exit 1 means incomplete/unavailable inspection or invalid arguments. Help exits 0.
Missing Git, absent/malformed metadata and unsafe source conditions are explained.
Broken installed commands require invocation from an intact trusted checkout.

Updated guide/help with owner-operated, explicitly reviewed tag-to-tag and branch
considerations. No automatic fetch, integration, link repair or rollback. The
published v0.1.0 workflows remain distinct from unreleased planned v0.1.1 behavior.
JACK_VERSION is unchanged. Existing SSH, setup, lifecycle and status behavior stays.

Files: `bin/jack`, `scripts/dev-check.sh`, `docs/guide.md`, this record.
